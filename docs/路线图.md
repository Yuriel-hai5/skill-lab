# 路线图 — 四个完善方向

**四个都想做。** 但不要同时开工 —— 按下面的顺序，一次一个，做完升版本号。

优先级判断依据：**先用起来，卡住的地方优先改。** 没被用到的问题不是问题。

---

## 现状盘点（截至 v1.1.2.0）

`workflow-recipes` 的 11 个配方：

| 配方 | 管什么 |
|---|---|
| 01 起步 | 想法模糊、方向没定 |
| 02 对齐 | 需求打磨、防止做偏 |
| 03 设计 | 从零做界面 / 改界面 / 查设计事实 |
| 04 规划 | spec 撰写、任务拆解、blocking 关系 |
| 05 实现 | 按 plan 写代码、TDD、原型 |
| 06 排错 | 报错、性能回退、间歇性 bug |
| 07 重构 | 架构改进、领域模型、测试补齐 |
| 08 协作 | 上下文管理、交接、追问澄清 |
| 09 学习 | 学技术、准备答辩 |
| 10 交付 | 提交前审查、解冲突、发布 |
| 11 配置文档 | 环境配置、CI/密钥、写文档与 skill |

**共同点：全都是「你在写代码」时用的。**
**缺口：你不写代码但必须做的事，一个都覆盖不到。**

---

## 方向 1 · 扩更多场景配方

**目标**：把"不写代码但必须做的事"也纳入进来。

### 具体要加的

| 新配方 | 管什么 | 什么时候用 |
|---|---|---|
| `12-thesis.md` | 文献怎么找、框架怎么定、章节怎么排、图表怎么规范、查重、答辩怎么准备 | 写毕设论文 / 课程论文 |
| `13-data-viz.md` | 拿到一堆数据 → 该用什么图、怎么配色、怎么讲清楚结论 | 做汇报、写报告、答辩 PPT |
| `14-deploy.md` | 项目怎么上服务器、域名 HTTPS、日志怎么看、出问题怎么回滚 | 部署上线、给别人演示 |
| `15-interview.md` | 简历怎么写、项目怎么讲、八股怎么背、手撕代码怎么练 | 找工作 |

### 具体例子（什么叫"扩"）

> 现在你说「我要写毕设论文」——
> `workflow-recipes` **对不上任何配方**。只能勉强塞进 09 学习，
> 但 09 讲的是"学一门技术"，不是"写一篇论文"。
>
> 加完 `12-thesis.md` 之后，它会给你一条序列：
> 定选题范围 → 文献综述（找什么、怎么筛）→ 定技术框架 →
> 章节骨架 → 图表规范 → 查重降重 → 答辩演练。
> 每一步产出什么、用哪个 skill，都写清楚。

### 验收标准

说一句"我要写论文"，能命中配方并给出多步序列 + 每步产出。

## 方向 2 · 工坊化

**目标**：从"一个 skill 的项目"变成"你的 skill 生产线"。

### 现在的问题

你想做新 skill（比如"自动整理课堂笔记"、"帮我精读英文论文"）时——
**没地方放**。只能又开一个对话、又建一个散落文件夹，最后自己都忘了在哪。

### 具体要做的

1. `skills/_template/` —— 新 skill 骨架（SKILL.md + frontmatter 模板 + references 目录）
2. `scripts/new-skill.py` —— 一条命令生成骨架：

```bash
python scripts/new-skill.py 读论文助手
# → skills/读论文助手/SKILL.md（结构已填好，直接改内容）
```

3. `scripts/deploy.py` 自动识别 `skills/` 下**所有** skill，不用手动列名单
4. `pack/build.py` 支持只打包指定的 skill

### 具体例子

```
skills/
├── _template/              ← 新 skill 从这复制
├── workflow-recipes/
├── ui-upgrade/
├── skill-pack-sharing/
└── 读论文助手/              ← 以后加的，自动被 deploy 识别
```

### 验收标准

`python scripts/new-skill.py 测试skill` 能生成一个结构完整、能直接被 WorkBuddy 加载的骨架。

## 方向 3 · 提升现有配方质量 ⭐ **建议第一个做**

**目标**：从"告诉你该干什么"变成"告诉你具体怎么干"。

### 现在的问题

配方里的话长这样：

> 建 feedback loop 定位 bug

**这话是对的，但你拿到不知道第一步干啥。**
（"看不懂选项"就是同一个根因 —— 太抽象，缺具体动作。）

### 改完长这样

> **Spring Boot 项目里，feedback loop 这样建**：
> ① IDE 下断点跑一遍，确认走的是不是你以为的那条路
> ② 加 `log.info` 打关键变量（别用 `System.out`）
> ③ 写最小单测复现 —— 只测那一个方法
> ④ 跟数据库有关就开 `spring.jpa.show-sql=true`，看真实 SQL
> ⑤ 还不行，用 `@Transactional` 隔离数据，看是不是脏读

### 具体要做的

对 11 个配方逐个过一遍，每个都补：

- **具体命令 / 具体文件 / 具体代码片段**（不要停留在"你应该做 X"）
- **技术栈专属例子** —— 你的主力栈是 Java / Spring Boot / Vue，优先给这些
- **"如果你没有 X 工具"的降级做法**（现在 00-skill-map 有了，但配方正文里也要提）
- **反例** —— 常见错误做法长什么样

### 验收标准

拿一个配方给不懂的人看，他能照着一步步做下来，不用回头问"那具体怎么弄"。

## 方向 4 · 优化分享安装体验

**目标**：让别人装上更可靠，或者换更简单的分享方式。

### 现在的状态

别人拖 zip 进来说"帮我装上"，能不能装上看运气：
- agent 可能不解压
- 可能把"装上"理解成"读一遍总结"
- 可能装错版本目录

### 可做的

| 做法 | 效果 |
|---|---|
| 包内加自检脚本 | 装完自己验证一遍，报告"装对了没" |
| 发到 GitHub | 别人直接 `git clone` 或下载，不用拖文件 |
| 做成 WorkBuddy 市场的 skill | 最省事，但要走审核 |
| 加一个"一键安装"的说明页 | 降低对方的理解成本 |

### 验收标准

找一个没用过的人试装，全程不问他问题，一次成功。

## 执行顺序建议

| 顺序 | 方向 | 为什么这个顺序 |
|---|---|---|
| **1** | 方向 3 · 配方质量 | 你马上要用。现在太抽象，自己都卡住 |
| **2** | 方向 1 · 扩配方 | 毕设要写论文，现在完全帮不上 |
| **3** | 方向 2 · 工坊化 | 等你真要做第二个 skill 时再搭，现在搭是空转 |
| **4** | 方向 4 · 分享体验 | 帮别人的，不是主线 |

> **但这只是建议。** 真正决定顺序的是：**你用的时候哪里卡住。**
> 卡住的地方优先改，记到 `docs/待改进.md`。

## 每个方向做完要做的

1. 更新 `CHANGELOG.md`
2. 升 `VERSION`（按四级规则）
3. `python scripts/deploy.py`
4. **新开对话**验证效果
