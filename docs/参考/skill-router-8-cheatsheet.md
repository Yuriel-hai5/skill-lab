# 8 个技能路由方案 · 速查表

> 一句话总览：**能直接用的只有 2 个**（pcx-wave 改一处路径、addyosmani 挑着装），其余 6 个的价值在「抄思路」，不在安装。

## 主表

| 方案 | 干什么的（说人话） | 配置项（说人话） | 结论 |
|---|---|---|---|
| **pcx-wave/skill-router** | 最轻的「默默帮你挑技能」：一个文本文件、300 行提示词搞定。门槛高——只有关键词明显对上才出手，不确定就不吭声；用了也只在回答末尾附一行小字 `*(via 技能名)*`。 | ① `/skill-router on --auto` —— 必须先手动敲一次才会自动干活，默认是关的；② `/skill-router stats` —— 看每个技能用了几次，从没用过的标 `never`；③ 扫描路径写死 `~/.claude/skills` —— 你要改成 `~/.workbuddy/skills` 和项目里的 `.workbuddy/skills`；④ 索引只读每个技能头部 20 行，总量压在 1000 tokens 内。 | ✅ 最接近你要的，改一处路径即可 |
| **addyosmani/agent-skills** | 不让模型瞎干的「操作规范集」：动手前先列假设、先拆任务、先写测试、提交前自检。25 个流程技能 + 1 个「该挑哪个」的总目录。 | ① 装哪几个 —— 用 `--skill 名字` 单个装，别全量；建议先要 `using-agent-skills`、`git-workflow-and-versioning`、`debugging-and-error-recovery`、`code-review-and-quality`；② 9 个斜杠命令 —— `/spec` 立需求、`/plan` 拆任务、`/build` 写码、`/test` 测试、`/constraints` 定质量标准、`/review` 审码、`/webperf` 查性能、`/code-simplify` 去冗余、`/ship` 发布；③ 装元技能时必须把 `references/` 一起搬，不然正文引用的文件会断链。 | ✅ 装，但只挑 3–5 个 |
| **obra/superpowers** | 最严的「规矩监督员」。规则是「哪怕只有 1% 可能用得上，也必须先用技能」，还专门列了一张表堵住模型偷懒的 12 种借口。 | ① `SessionStart` hook —— 会话一开就自动加载规矩，不装 hook 就不生效；② 14 个技能 —— 头脑风暴 → 写计划 → 执行 → TDD → 系统调试 → 验证 → 审查 → 收尾；③ 优先级规则 —— 流程技能先于领域技能（先定方法，再干活），这条值得抄。 | ⚠️ 整包别装（强制播报「正在用 XX 技能」，跟静默相反） |
| **hussi9/skill-router** | 重型全自动路由：带仪表盘、学习、体检。工程化最完整，依赖也最重。 | ① 6 个 hook 事件 —— 用 `install_hooks.py` 往 `settings.json` 里接；② `IRON RULE … hard` —— 硬拦：技能没加载就不让改文件（Edit / Write / Task 直接被拒）；③ `Soft route …` —— 软提示，不拦；④ `build_index.py --enrich` —— 可选用小模型增强匹配，要 `GEMINI_API_KEY`。 | ❌ 别装（会拦你改文件，还要 API key） |
| **Liber1917/skill-router** | 唯一明写支持 WorkBuddy 的，扫描路径表里自带 `.workbuddy/skills`。但它的哲学是「每次都要问人」。 | ① 置信度 0.85 以上算高度匹配 —— 即便这么高，它仍然要先问你一句「加载这个 skill 吗」；② `[skill-router]` 前缀 —— 每行输出都带，用来事后审计，代价是每轮加噪音；③ 联网装技能 —— 本地没匹配就上网搜并自动装（`-y` 自动确认），这是供应链风险，要删；④ 多技能编排 —— 遇到「又…又…」的需求，给三个选项：串行 / 分工 / 只跑一个。 | ⚠️ 可当骨架，但要改三处（前缀默认关、高置信别问、联网装技能删掉） |
| **jmagly/aiwg** | 靠「目录里有什么文件」猜你项目做到哪一步了。 | ① 判定源是 `.aiwg/` 目录（`planning/phase-status.md`、`gates/`、`risks/`）—— 没装它的框架就读不出阶段；② 脚本开关 —— `--full` 全量、`--tech-stack` 只看技术栈、`--aiwg-state` 只看阶段、`--team` 团队信息。 | ⚪ 不装，只抄它两张表（文件 → 项目类型、产物 → 阶段） |
| **jim80net/memex-claude** | 真语义搜索：本地跑个小模型算相似度，每轮只把相关的技能 / 记忆 / 规则塞进上下文。 | ① 3 个 hook —— `UserPromptSubmit`（每轮提问）、`Stop`（收尾）、`PreToolUse`（用工具前）；② 索引源 —— `~/.claude/rules`、`~/.claude/skills`、`~/.claude/projects/<项目>/memory`，全要改；③ 7 类知识分流 —— rule / memory / skill / workflow / tool-guidance / session-learning / stop-rule；④ 披露档位 —— 技能只给一行简介（真要用才读全文）、记忆直接给全文、规则第一次给全文之后压成一行；⑤ 模型 `all-MiniLM-L6-v2`，离线免 key。 | ⚠️ Windows 上别装（要装二进制 + 外部包）；抄「技能索引只存名字和简介、不存正文」 |
| **skill-conditions** | 不是工具，是一份设计方案。整个目录只有一个 `SKILL.md`，里面的「实现」是 JS 伪代码。 | ① `paths` —— 按文件路径匹配（`**/*.py`、`**/Dockerfile*`）；② `exclude` —— 排除；③ 冲突规则 —— 更具体的赢，一样具体按字母序，不冲突的全激活；④ 60 秒宽限期。 | ❌ 不能装（装它不干活）；抄「按当前在动什么文件」判阶段这路信号 |

## 术语（4 个词够用）

| 词 | 说人话 |
|---|---|
| `SKILL.md` | 技能本体，一个文件夹一个 Markdown。文件头的 `description` 决定它什么时候被调用 |
| hook（钩子） | 会话开始 / 每次提问 / 用工具前自动跑一段脚本。**能改造路由，但要按客户端逐个接线** |
| 高置信匹配 | 「关键词明显对上」才算命中。「修一下这个 bug」太泛 → 不路由 |
| 静默 | 默默用、不说。代价是**调错了你查不到原因**，所以必须留个事后可查的出口 |

## 三句结论

1. 你要的「读全部 + 判阶段 + 完全静默 + 零 hook」，**8 个里没有一个同时满足**。
2. 最省事的路：**pcx-wave 改一处路径**，先用两周，看它能不能治「装了不用」。
3. 最值钱的东西不是代码，是三条经验：**技能索引只存名字和简介**（省上下文）、**流程技能优先于领域技能**（优先级）、**路由会悄悄失效，必须能自查**（作者自曝路由死了两个月没人发现）。
