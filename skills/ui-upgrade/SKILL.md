# UI Upgrade — 已有界面的质感与动效升级

这是一个**编排型** skill：界面已经能跑、结构基本不动，目标是把视觉品质和动效拉到"看起来像人设计的"。
它自己不产出设计，而是按固定顺序驱动三个下游 skill。

> 本 skill 是 `workflow-recipes` 的 [03-design](../workflow-recipes/references/03-design.md) 配方 B 的展开版本。
> 用户描述更宽泛的处境（"我现在到 XX 阶段了"、"下一步该做什么"）时，由 `workflow-recipes` 接手编排。

## 边界

**用**：界面已完成、结构不动，要提升视觉质感 / 动效 / 高级感。

**不用**：
- 从零做新页面 → `finesse-ui`（按 register 走完整流程）
- 要换设计语言、推倒重做 → `impeccable` 的 redesign 路径 或 `redesign-skill`
- 只查一个具体事实（某个配色、某个规范）→ 直接用 `ui-ux-pro-max`

---

## 第 0 步：锁定三个变量（动手前必须问清或自己查清）

| 变量 | 为什么要 | 怎么定 |
|---|---|---|
| **register** | 决定用哪套标准，选错全盘错 | 后台 / 工具 / 数据表 / 设置 → **product**；官网 / 落地页 / 作品集 → **brand**；只在手机上 → **h5** |
| **技术栈** | 决定动效走哪条路线 | 读 `package.json` / `pubspec.yaml` / 现有代码。**不猜**——猜错会推荐装不上的依赖 |
| **现状痛点** | 决定先修什么 | 跑一次 `impeccable audit`，别凭感觉 |

register 是 product 时，**禁止**把 brand 语法灌进来：grain、vignette、巨型 hero 字体、hero 引擎、暗色默认。
dashboard 不是"带图表的品牌页"。

## 第 1 步：审计定位 → 产出问题清单

```
impeccable audit <target>        # 技术层：a11y、性能、响应式
impeccable critique <target>     # UX 层：启发式评分
```

**产出**：一份按严重度排序的问题清单，每条写清「屏幕上看到什么 + 对用户造成什么代价」。
用用户能懂的话，不要甩内部术语（`eyebrow`、`scrim`、`hairline` 这些要翻译）。

不要跳过这步直接改。没有清单的"升级"就是凭感觉换配色。

## 第 2 步：质感升级 → 按黑名单逐条过

标准来自 `finesse-ui/references/anti-cheap.md`（廉价黑名单）和 `design-dna.md §1`（通用工艺底线）。
**这两条要真读**，下面是必须命中的硬项：

### 硬禁（发现即改，无例外）

- **纯 `#fff` / `#000`**，硬 `#333` 边框，浅底上未着色的黑色投影 → 换**着色中性色**、半透明边框、**同色相阴影**
- **AI 紫/蓝辉光**——紫色渐变按钮、霓虹网格背景、发光 CTA 当默认 → 中性底 + 一个高对比强调色
- **假精确数字**（`92%`、`4.1×`、`48k` 编出来的）→ 用真实数据，或标为示例，或删掉
- **`<div>` 手搓假截图 / 假浏览器栏 / 假手机框 / 假终端窗** → 真截图，或者干脆不要 chrome
- **文案里用破折号做设计装饰** → 用句号、逗号，或重写句子

### 高频 AI 味（默认要改，除非能说出理由）

- **每节都有 eyebrow**（标题上方那行小号大写字母标签）→ **每 3 节最多 1 个**
- **一模一样的卡片网格**（6 张卡，图标+标题+段落，尺寸全同）→ 变尺寸、变跨度、给 2–3 个格子真实视觉差异
- **同一版式重复出现** → 一个版式家族最多用 2 次
- **`border-left: 3px` 侧边强调条** → 全边框、底色、前置图标，或不要
- **glassmorphism 当默认装饰** → 只在有理由时用，且补 1px 内边框 + 内阴影 + 降透明度回退
- **按钮对比度不足**（白底白字、幽灵按钮压在照片上无衬底）→ 每个 CTA 查：文字 vs 按钮底 ≥4.5:1（18px+ 粗体 ≥3:1）
- **表单对比度不足**（近白 placeholder 压在近白输入框、错误提示文字太浅）→ 每个 input / placeholder / focus ring / 错误串都要查
- **反射式默认字体**（Inter / Fraunces / Playfair / Cormorant / Space Grotesk / DM Sans / Lora / IBM Plex / Space Mono 无理由就用）→ 换更少被用滥的（Geist、Cabinet Grotesk、PP Neue Montreal、GT Walsheim、ABC Diatype）
- **"创意/高级 = 衬线"反射** → 默认无衬线展示体，衬线只在真编辑/奢华/传承且有理由时用
- **米色 + 黄铜 + 浓缩咖啡**这套 2026 饱和默认（`#f5f1ea` 系底色 + `#b08947` 系强调）→ 换：冷奢（银灰+铬+烟）、森林（深绿+骨白+琥珀）、黑褐（真近黑+暖褐）、钴蓝+奶油、陶土+石板、橄榄+砖红，或纯单色 + 一个饱和点缀

### 两级反射检查（先跑这个）

- **一阶**：光看**类别**能猜出主题和配色吗？（"咖啡 → 暖米色 + 黄铜衬线"）能 → 这就是训练数据的第一反射，重做
- **二阶**：看**类别 + 你的反向参考**能猜出美学吗？（"不是 SaaS 奶油风的 AI 工具 → 编辑排版风"）能 → 这是更深的陷阱，继续重做

两个答案都必须**不显然**。

### 工艺底线（无例外，全部适用）

- surface 分层：每级只差几个百分点的亮度（暗色底 → +7% → +9% → +12%）
- 输入框比周围**更深**（它是内嵌的，接收内容）
- 侧边栏与画布**同底色**，靠一条细边框分隔，不要换色
- **squint test**：眯眼看，还能感知层级，但没有任何东西跳出来
- 层级靠**留白和色调**，不靠线

## 第 3 步：动效 → 先过门禁，再选路线

方案来自 `finesse-ui/references/motion.md`。**先读它**，别凭印象加动画。

### 门禁四项（写第一行 keyframe 前必须全过）

1. **有动机**：每个动效要能写出一句理由（层级 / 理解 / 反馈 / 状态 / 身份）。「看起来很酷」不是理由
2. **删掉还能用**：把所有动画去掉，页面必须仍然可读、完整、可导航。动效是增强，**永远不是结构**
3. **有终态**：`prefers-reduced-motion: reduce` 不是"关掉"，是一个**设计好的静止帧**。和动效同时设计，不要事后补
4. **60fps 否则简化**：只动 `transform` 和 `opacity`。动 `width` / `top` / `filter` / `box-shadow` 会重排重绘

```js
const RM   = matchMedia('(prefers-reduced-motion: reduce)').matches;
const FINE = matchMedia('(hover: hover) and (pointer: fine)').matches;
// RM → 直接设终态；指针驱动的效果用 FINE 挡在触屏外
```
```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: .01ms !important; transition-duration: .01ms !important; }
}
```

> **关键**：动画元素要**在终态下编写**，从别处动**过来**。写成 `opacity: 0` 等动画触发才显示，
> 在降级模式下会**永久不可见**。

### 六条路线：从 R1 开始，停在第一条能干这活的

| 路线 | 成本 | 擅长 | 降级时的静止形态 | 典型翻车 |
|---|---|---|---|---|
| **R1 CSS transition/keyframes** | 0 | 状态变化、微交互、入场、环境循环 | 终态（本来就写好了） | 想用它做时序编排（没有 timeline） |
| **R2 原生滚动驱动** `animation-timeline` | 0 | 视差、进度、逐项到达、吸顶显现 | 中间进度帧 | 没有 `pin`、不能跨元素编排；需要无支持时的降级路径 |
| **R3 View Transitions + WAAPI** | 0 | 列表增删、筛选重排、路由切换、展开收起 | 瞬时切换，不补间 | 忘了做未过渡回退，老浏览器硬闪 |
| **R4 GSAP + ScrollTrigger** | ~60KB | pin 住的叙事、横向轨道、scrub | 杀掉 scrollTrigger，tween 设到终点 | **拿它干 R1/R2 免费的活——最常见的过度设计** |
| **R5 Canvas / WebGL** | 100–160KB | 粒子、场、流体、材质、后处理 | 渲染一帧然后停循环 | DOM 没了：文字不可选、图片不被索引、无法懒加载 |
| **R6 零依赖 CSS 3D 空间** | 0 | 摄像机在 DOM 面板场景中移动 | 摄像机停在最佳构图 | 画家算法遮挡问题 |

**选择顺序：从 R1 开始，停在第一条能胜任的。** 唯一可以跳级的理由：效果真的只有那条路线才有
（要 `pin` → R4；要逐像素材质 → R5）。

**R5 的真实成本不是 KB 是 DOM**：内容一旦变成纹理就不再是内容。当"3D"的东西是照片和文字时，**R6 优于 R5**。

### 十条效果族（按内容挑，不按"哪个炫"挑）

空间（长廊 / 星球 / 圆环 / 隧道 / 螺旋）· 粒子场 · 逐字与排版 · 重排与 FLIP · 材质与光 · 视差层 ·
遮罩与揭示 · 色彩与滤镜 · 物理与惯性 · 环境循环

每一族都要问：**它的 slop form 是什么？**（被发过太多次、现在读起来就是 AI 味的那版）——查 `motion.md §2`。

### GSAP 预设（走 R4 时查这个）

```
python <skills-dir>/ui-ux-pro-max/scripts/search.py "<关键词>" --domain gsap
```
返回带完整代码片段 + Duration / Easing / Do / Don't 的方案（17 个预设）。

**改造场景不要用** `finesse-ui` 的 `hero-engines.md`——那是 brand register 从零做 hero 用的。

## 第 4 步：收尾验证 → 产出交付说明

```
impeccable polish <target>
```

**有界验证，不是无限循环**：改完 → 一次性批量截图检查（桌面 + 移动一起）→ 一批修完 → 最多再确认一轮 → **停**。
开放式自我 QA 是在烧用户的钱。

**产出**（给用户看的）：

```
## 改了什么
- 质感：[逐条列，每条写"屏幕上原来什么样 → 现在什么样"]
- 动效：[逐条列，每条写 效果 + 路线 + 为什么用这条路线]

## 没动什么
- [明确说明保留了哪些结构和内容，让用户放心]

## 降级表现
- prefers-reduced-motion 下：[说明每个动效的静止帧]
```

## 铁律

1. **不重新设计。** 结构、内容、文案、交互行为全部保留。只动视觉与动效。
2. **一次只让一个流程型主导。** 本 skill 主导编排；`impeccable` 出命令与检查，`finesse-ui` 出标准，`ui-ux-pro-max` 出事实。不要让它们各自跑完整流程。
3. **先审计后动手。** 没有问题清单就开始改 = 凭感觉换配色。
4. **动效删掉后页面必须仍然可用。** 这条不满足，动效就是 bug 不是特性。
5. **改完说清改了什么、没动什么、降级怎么办。** 用户要能判断该不该接受。
